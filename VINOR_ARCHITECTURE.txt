================================================================================
                    مستند فنی معماری Vinor
                    تاریخ: ۱۴۰۵/۰۴/۲۵
                    Doc Version: v1.4
================================================================================

این سند وضعیت فعلی کدبیس Vinor را بدون پیشنهاد پیاده‌سازی توصیف می‌کند.
Vinor یک Flask monolith برای بازار املاک محلی (گرمابسرد، دماوند) با پنل
همکاران اکسپرس، چت AI مبتنی بر DeepSeek، و ذخیره‌سازی عمدتاً JSON فایل است.

================================================================================

+---------------+--------------------------------+-----------------------------+
                |                                |
                v                                v
+---------------------------+    +---------------------------------------------+
|     Domain Services       |    |              AI Layer                        |

1.2 اتصال Frontend، Backend، Database و AI
------------------------------------------

لایه          | نقش                              | اتصال
--------------|----------------------------------|----------------------------------
Frontend      | قالب Jinja2 + Tailwind/Alpine    | HTTP به Flask؛ چت AI از
              | در express_partner و admin       | POST /express/partner/ai/chat
              |                                  | و POST /ai/chat
Backend       | Flask 2.3 App Factory            | Blueprintها؛ سرویس‌ها در
              | app/__init__.py                  | app/services/, express_partner/, ai/
Database      | JSON در instance/data/           | storage.py — منبع حقیقت داده
              | (SQLAlchemy بدون db.Model)       | sqlite فقط initialize می‌شود

              | + Function Calling               | context از JSON lands/partners

نکته: سیستم SPA جدا (React/Vue) ندارد. UI با سرور رندر می‌شود و چت AI با
fetch/XHR به JSON endpointها متصل است.

2. AI Layer
================================================================================

2.1 مدل AI
----------
Provider:     DeepSeek API (DEEPSEEK_BASE_URL, DEEPSEEK_API_KEY)
مدل‌ها:       deepseek-v4-flash و deepseek-v4-pro
انتخاب:       پنل ادمین -> settings.json -> ai.model_choice
              مقادیر: auto | flash | pro
پیش‌فرض:      auto و flash هر دو به Flash map می‌شوند
فایل:         app/ai/runtime_settings.py

اولویت کلید API:
  1. settings.json -> ai.api_key
  2. متغیر محیطی DEEPSEEK_API_KEY
  3. api_keys.py (ریشه پروژه)
فایل:         app/keys.py


2.2 محل Promptها
----------------
نوع                    | فایل                    | محتوا
-----------------------|-------------------------|---------------------------
System Prompt اصلی     | app/ai/config.py        | VINOR_AI_PUBLIC_PROMPT
                       |                         | VINOR_AI_PARTNER_PROMPT
                       |                         | VINOR_AI_SPECIAL_PROMPT
راهنمای Agent          | app/ai/agent_tools.py   | agent_system_hint()
نیت چیپ‌های سریع       | app/ai/intents.py       | CHIP_INTENT_HINTS
Escalation marker      | app/ai/config.py        | [[ESCALATE:...]]


2.3 مدیریت System Prompt
-------------------------
جریان در _build_messages() — app/ai/services.py:

  1. prompt_for_voice(voice) — یکی از سه پرامپت بر اساس مخاطب
  2. اگر with_tools=True -> agent_system_hint(voice)
  3. اگر chip_intent -> hint از intents.py
  4. اگر user_key -> context دینامیک از _build_system_prompt()

Voice/Audience — app/ai/audience.py:
  - public   : مشتری / خریدار
  - partner  : همکار پورسانت‌گیر (واسط فروشنده و خریدار)
  - special  : مالک/فروشنده ویژه (بالاترین دسترسی)


2.4 ساخت Context
-----------------
فایل اصلی: app/ai/context.py
کش:        app/ai/context_cache.py

مخاطب Partner:
  - build_partner_context_base(phone)     — بخش ثابت، کش per phone
  - build_partner_status_context(phone)   — وضعیت زنده (مأموریت، پورسانت، اقدام فوری)
  - build_partner_land_context(...)       — بر اساس پیام کاربر و focus_codes

مخاطب Public:
  - build_public_context_base()           — کش global
  - build_public_land_context(...)        — نمونه فایل‌ها + جستجوی heuristics

Context از خواندن JSON ساخته می‌شود:
  lands.json, express_assignments, express_partners,
  express_visit_requests, partner_missions, settings, ...

محدودیت طول: max_context_chars (پیش‌فرض 3000 کاراکتر)
فوکوس گفتگو: recent_thread_land_codes() از chat_store — حداکثر 3 کد ملک اخیر thread

خلاصه ملک (_land_summary) شامل:
  کد، عنوان، شهر، محله، نوع، قیمت، متراژ، وضعیت تخصیص، پورسانت


2.5 Memory (حافظه گفتگو)
------------------------
فایل: app/ai/chat_store.py
مسیر: instance/data/ai_chats/{audience}/{phone}.json

ساختار:
  threads[] -> هر thread دارای messages[]
  هر message: role, content, land_codes, agent_actions, ...

محدودیت‌ها:
  - 80 پیام per thread
  - 30 thread per user (مهمان: 2 thread)
  - max_history ارسالی به مدل: 5 پیام (قابل تنظیم در settings)

حافظه بلندمدت معنایی (vector / long-term memory) وجود ندارد.
فقط JSON per-user و context snapshot در هر درخواست.


2.6 سایر مکانیزم‌های AI
------------------------
Credits:     app/ai/credits.py
             - rate limit (min_interval_sec)
             - dedup پاسخ تکراری
             - سقف 20 پاسخ برای مهمان بدون لاگین
             - notify ادمین در صورت اتمام balance API

Escalation:  app/ai/escalations.py
             - marker [[ESCALATE:خلاصه]] در پاسخ مدل
             - ذخیره سوال -> پاسخ ادمین -> inject در چت بعدی

Postchi:     app/services/postchi.py
             - thread جدا __postchi__ برای پیام‌های رسمی وینور (غیر-AI)

3. Agent Logic
================================================================================

3.1 Chatbot یا Agent؟
---------------------
Agent محدود با Function Calling — نه chatbot ساده.

ویژگی‌ها:
  - حداکثر 2 دور tool call (_MAX_TOOL_ROUNDS در services.py)
  - ابزارها در agent_tools.py؛ schema بر اساس voice
  - اکشن‌های حساس با کارت تأیید + confirm_action_from_token()
  - تا تأیید کاربر، ثبت واقعی (بازدید/معامله/همکاری) انجام نمی‌شود


3.2 تصمیم‌گیری AI
-----------------
جریان generate_reply():

  User message
      |
      +-- credit guard / guest limit
      +-- chip_intent == "visit" -> clear_visit_draft
      +-- try_continue_visit_from_user_message()
      |       -> rule-based short-circuit (بدون فراخوانی API)
      |
      +-- _build_messages() + _run_agent_loop()
              |
              +-- call_ai() -> tool_calls?
              |       +-- run_tool() -> نتیجه به messages
              +-- پاسخ نهایی
                      +-- [[ESCALATE]] -> escalations
                      +-- [[LAND:کد]] -> land_cards
                      +-- agent_actions -> UI cards


3.3 Workflow درخواست کاربر
--------------------------

مشتری (public):
  1. POST /ai/chat یا redirect به /express/partner/home?ai=1
  2. generate_reply() با tools:
     search_lands, get_cooperation_info, get_application_status,
     propose_partner_application
  3. پاسخ + کارت ملک / کارت ثبت همکاری

همکار (partner):
  1. POST /express/partner/ai/chat (نیاز به session)
  2. tools:
     search_lands, suggest_next_action, draft_listing_copy,
     propose_visit_request, propose_complete_visit,
     propose_deal, propose_release_deal
  3. POST /express/partner/ai/agent/confirm برای تأیید اکشن

Rule-based bypass:
  جریان چندمرحله‌ای بازدید (try_continue_visit_from_user_message)
  بدون فراخوانی مدل ادامه می‌یابد.


3.4 ابزارهای Agent (Function Calling)
--------------------------------------
مشترک (همه voiceها):
  search_lands

Public voice:
  get_cooperation_info
  get_application_status
  propose_partner_application

Partner / Special voice:
  suggest_next_action
  draft_listing_copy
  propose_visit_request
  propose_complete_visit
  propose_deal
  propose_release_deal

فایل: app/ai/agent_tools.py

5.3 ارتباط User، Property، Conversation و Transaction
------------------------------------------------------

User (phone)
  |
  +-- express_partners          (پروفایل همکار)
  +-- express_assignments       (land_code -> partner_phone)
  +-- express_visit_requests    (partner + land + customer)
  +-- express_commissions       (tx_mode: visit | deal | deal_pending | ...)
  +-- partner_missions          (land_code + thread seed)
  +-- ai_chats                  (threads/messages per audience)

Land (code)
  |
  +-- در lands.json
  +-- assignment.status: active | in_transaction | sold | pending | ...
  +-- visit_requests و commissions مرتبط با land_code

Conversation
  -> bind به User با phone/user_key و audience (public | partner)
  -> thread_id برای جداسازی گفتگوها (شامل __postchi__ برای پستچی)

Transaction
  -> express_commissions + state مأموریت/assignment
  -> tx_mode در sales_coach.py و agent_tools هم‌راستا می‌شود:
     visit, visit_commission_pending, deal, deal_pending, release, blocked, ...


5.4 SQLite
----------
مسیر: sqlite:///instance/vinor.db
وضعیت: initialize می‌شود (db.create_all) ولی بدون schema فعال.
منبع حقیقت: JSON files.

9. Current AI Capability
================================================================================

9.1 Vinor الان چه کارهایی انجام می‌دهد؟
----------------------------------------

برای مشتری (public):
  - جستجوی ملک در گرمابسرد (search_lands)
  - توضیح سطوح / شرایط / مسیر همکاری
  - وضعیت درخواست همکاری
  - پیشنهاد کارت ثبت همکاری (با تأیید کاربر)
  - ارجاع سوال به ادمین ([[ESCALATE]])

برای همکار (partner / special):
  - پیشنهاد «کار بعدی» از وضعیت داشبورد
  - متن آگهی دیوار / اینستا (draft_listing_copy)
  - ثبت بازدید چندمرحله‌ای با کارت تأیید
  - «بازدید انجام شد»، ثبت معامله، انصراف از معامله
  - جستجوی فایل + کارت ملک
  - آگاهی از مأموریت فعال و tx_mode

غیر-AI ولی مرتبط:
  - Sales Coach: پیامک/اعلان rule-based سه‌بار در روز (10، 14، 20 تهران)
  - Partner Missions: تخصیص فایل رندوم + seed پیام اول چت
  - Postchi: inbox رسمی (بدون LLM)

برای تبدیل Vinor به یک Vertical AI Real Estate Agent کامل، شکاف‌های

10.1 شکاف‌های لایه AI
---------------------

  - QdrantVectorStore (adapter)
  - ChromaVectorStore (adapter)

- مسیر اصلی production:
  - User query -> EmbeddingProvider -> VectorStore.search -> property_codes
- مسیر fallback/dev:
  - در هر خطای provider/store، LandsRagRetriever به TfidfFallbackRetriever سوییچ می‌کند

12. Optimization Sprint (Production Performance)
------------------------------------------------

12.1 Token Optimization (Instrumentation + Runtime)
- افزودن ماژول تحلیل توکن:
  - app/ai/token_analytics.py
- ثبت analytics برای هر درخواست AI در:
  - instance/data/ai_token_analytics.jsonl
- فیلدهای ثبت‌شده:
  - input_tokens
  - output_tokens
  - system_prompt_tokens
  - context_tokens
  - history_tokens
  - rag_tokens
  - total_tokens
  - total_cost (configurable by env rates)
  - response_time_ms
  - api_rounds
  - provider/model/cache_hit

12.2 Dynamic Context
- مسیر قبلی حفظ شده و رفتار کاربر تغییر نکرده است.
- Context ملک همچنان فقط در queryهای مرتبط وارد می‌شود (منطق قبلی حفظ شده).
- Prompt core context cache با TTL کوتاه اضافه شد تا build تکراری کاهش یابد:
  - _PROMPT_CACHE در app/ai/services.py

12.3 Conversation Compression
- قابلیت فشرده‌سازی history قدیمی اضافه شد ولی پیش‌فرض خاموش است:
  - VINOR_HISTORY_SUMMARY=0 (default)
  - در حالت فعال، فقط وقتی summary از پیام‌های حذف‌شده کم‌هزینه‌تر باشد استفاده می‌شود.
- هدف: جلوگیری از افزایش token و حفظ رفتار پیش‌فرض فعلی.

12.4 Smart RAG
- Dynamic Top-K در retriever اضافه شد (کوتاه/بلند بودن query).
- Metadata filtering قبل از retrieval اعمال می‌شود (city/category/status/price/area/tags).
- Dedup در سطح property_code حفظ شده است.

12.5 Incremental Index
- RAG index از حالت full re-embed به incremental تغییر کرد:
  - signature per property
  - re-embed فقط برای اسناد تغییرکرده
  - حذف اسناد پاک‌شده بدون rebuild embedding کامل
- فایل: app/knowledge/rag/retriever.py

12.6 Cache Layers
- Embedding Cache: hash(text)->vector در retriever
- Retrieval Cache: TTL cache روی query/filt/top_k/allowed
- Prompt Cache: TTL cache برای core context build
- Response Cache: مسیر قبلی credits.py حفظ و فعال
