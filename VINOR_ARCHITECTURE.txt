وضعیت سند
----------
این سند وضعیت واقعی کدبیس Vinor در تاریخ بالا را توصیف می‌کند. منبع حقیقت،
کد اجراشونده و Registry/Configهای پروژه است؛ ROADMAP و Change Log صرفاً سابقه
تکامل‌اند. اعداد benchmark تاریخی، تضمین production نیستند.

دامنه بازبینی:
  app/، admin/، scripts/، tests/، run.py، passenger_wsgi.py، config.py،
  requirements*.txt، route/agent/workflow registryها و قراردادهای storage.

اصل امنیتی مستندسازی:
  هیچ API key، شماره کاربر، محتوای چت، داده ملک یا مقدار حساس runtime در این
  سند بازنشر نشده است.


================================================================================
1. خلاصه اجرایی
================================================================================

Vinor یک Flask monolith برای عملیات فروش املاک است که این اجزا را در یک
application واحد ترکیب می‌کند:

  - سایت عمومی و صفحه ملک
  - پنل Express Partner و نقش‌های Buyer/Seller/Owner
  - پنل Admin، RBAC، Audit، SMS و AI Mission Control
  - قیف کسب‌وکار Lead تا Visit، Offer، Contract، Deal و Settlement
  - دستیار DeepSeek با Conversation/Workflow، RAG، Memory و Function Calling
  - شش Agent تخصصی با اجرای موازی، Decision Engine و Business Intelligence
  - لایه‌های Goal، World Model، Long Planner، Evaluation و Reflection
  - موتورهای background برای Optimization، Learning، Improvement و Business AI

معماری فیزیکی:

  Client
    Jinja2 + Tailwind + Alpine.js + Vanilla JS + Partner PWA
      |
      v
  Flask Application Factory (app/__init__.py)
      |
      +-- Public / Partner / Role Portals / Admin / JSON APIs
      |
      +-- Business OS
      |     Foundation -> CRM -> Visit Result -> Commercial -> Closing
      |     Roles -> Integration Journey -> Hardening
      |
      +-- AI Request Pipeline
      |     Conversation -> Executive/Goals -> Supervisor -> Agents
      |     -> Decision/BI/World/LongPlan -> Adaptive
      |     -> Memory/RAG/Planning/Tools/LLM
      |     -> Evaluation/Reflection
      |
      +-- External Services
      |     DeepSeek, SMS.ir, Firebase/FCM, Web Push, Git Webhook
      |
      v
  Persistence
    instance/data/*.json + *.jsonl + subdirectories
    instance/vinor.db (SQLAlchemy initialized; no active db.Model)

سبک معماری:
  - Monolith ماژولار، نه microservice
  - Server-rendered، نه SPA
  - JSON-first، نه relational-domain-first
  - DI و Protocol در لایه‌های AI جدید
  - Rule-first و fail-open در orchestration داخلی
  - Human-in-the-loop برای mutationهای حساس AI
  - Additive compatibility با قیف legacy همکار

2.1 نقاط ورود
---------------

run.py
  - create_app() را صدا می‌زند و app را export می‌کند.
  - dev server را با FLASK_RUN_HOST/PORT اجرا می‌کند.
  - FLASK_DEBUG در run.py به‌صورت پیش‌فرض ON است.
  - Rotating log را در instance/logs/app.log تنظیم می‌کند.
  - favicon و JSON 404 handler را فراهم می‌کند.

passenger_wsgi.py
  - entrypoint تولید روی cPanel/LiteSpeed/Passenger است.
  - INSTANCE_PATH را روی مسیر production قرار می‌دهد.
  - schedulerهای in-worker را OFF می‌کند تا worker نگه داشته نشود:
      VINOR_SALES_COACH_SCHEDULER=0
      VINOR_CELEBRATION_SMS_SCHEDULER=0
      VINOR_ADMIN_SMS_SCHEDULER=0
      VINOR_OPTIMIZATION_SCHEDULER=0
  - application را از run.app می‌گیرد.

app/__init__.py
  - Flask application factory
  - config، session، proxy، CORS، CSRF، SQLAlchemy و Blueprintها
  - PWA root routes و landing gate
  - Firebase bootstrap
  - start اختیاری schedulerها

Public REST API v1 قدیمی حذف شده است. مسیرهای فعلی باید از Registry و route
decoratorهای بالا استخراج شوند، نه از اسناد قدیمی API v1.

3.2 Session و Proxy
-------------------

  - نام cookie: vinor_session
  - HttpOnly و SameSite=Lax
  - lifetime پیش‌فرض بلندمدت (۱۸۰ روز)
  - TRUST_PROXY در کد به‌صورت پیش‌فرض ON و ProxyFix فعال است.
  - SESSION_COOKIE_SECURE با وضعیت proxy/production هماهنگ می‌شود.
  - SECRET_KEY باید در production از env تأمین شود؛ fallback توسعه‌ای کافی نیست.

3.3 CSRF و CORS
---------------

  - Flask-WTF برای فرم‌های HTML فعال است.
  - XSRF-TOKEN برای پاسخ‌های HTML تنظیم می‌شود.
  - endpointهای webhook و APIهای JSON منتخب، از CSRF معاف‌اند.
  - CORS روی /api/* تعریف شده است.
  - Mutationهای Admin علاوه بر login با RBAC لایه Hardening محدود می‌شوند.

3.4 Landing gate و PWA
----------------------

  - کاربر ناشناس در مسیرهای غیرعمومی به Partner Home هدایت می‌شود.
  - public allowlist شامل landing، property/express، AI public و health است.
  - /sw.js به Service Worker پنل همکار هدایت می‌شود.
  - manifest عمومی fallback دارد؛ Partner manifest و SW مستقل نیز موجود است.
  - PWA ماهیت partner-centric دارد و نباید به‌عنوان SPA سراسری توصیف شود.

================================================================================
8. جریان واقعی generate_reply
================================================================================

مرجع: app/ai/services.py

  1. تنظیم flask.g برای thread، audience، focus land و پیام کاربر
  2. ai_config و service-enabled guard
  3. credit/rate/dedup/guest guard؛ امکان early return
  4. normalize chip intent
  5. Conversation Engine
       handled + no handoff:
         Executive goals-only + Goals -> return بدون LLM
       pass-through:
         ادامه pipeline
  6. Executive plan و Goal Engine
  7. Supervisor route/policy
  8. Agent preparation
       default parallel:
         DAG agents -> Decision -> BI -> World Model -> Long Plan
       fallback:
         sequential single-agent
  9. Adaptive begin و after-agent-prepare
 10. reset visit draft در chip مربوط
 11. rule-based visit continuation؛ امکان early return
 12. schema ابزارها با Supervisor gate
 13. build messages:
       prompt + context/RAG + memory + history/summary
 14. Planning:
       compact hint + safe tool seeds
 15. Agent hint priority:
       Decision > Parallel Merge > per-agent hints
 16. DeepSeek agent loop
 17. post-process:
       escalation، land codes/cards، agent actions و HTML cards
 18. Adaptive after-response یا fail
 19. response dedup cache
 20. Memory learn_from_exchange
 21. token analytics -> evaluation -> self-reflection
 22. route handler append_exchange به chat_store

نکات مهم:
  - Decision، BI، World Model و Long Planner در مسیر live به branch اجرای
    Parallel Agents وابسته‌اند.
  - Conversation form و visit continuation می‌توانند کل LLM path را دور بزنند.
  - Stateهای Supervisor/Adaptive/Executive عمدتاً object روی flask.g هستند و
    خودشان وارد Prompt نمی‌شوند.
  - BI object تولید می‌شود؛ با وجود flag مربوط، BI hint مستقلی در message
    injection فعلی wire نشده است.

10. Knowledge، RAG، Memory و Planning

10.1 RAG
---------

Vinor اکنون RAG دارد؛ هر ادعای «RAG/Embedding/Vector Search وجود ندارد» تاریخی
و منسوخ است.

مسیر:
  app/knowledge/

Contracts:
  PropertyRetriever
  EmbeddingProvider
  VectorStore

Bridge:
  app/ai/context.py::_select_lands_by_rag

قرارداد خروجی:
  فقط property_code؛ متن Prompt و _land_summary از land object فعلی ساخته می‌شود.

Provider adapters:
  OpenAI، DeepSeek، BGE، Jina

Vector store adapters:
  InMemory، FAISS، Qdrant، Chroma

Default:
  VINOR_EMBEDDING_PROVIDER=deepseek
  VINOR_VECTOR_STORE=inmemory

Fallback:
  TF-IDF retriever در خطای provider/store یا محیط dev

ویژگی‌ها:
  metadata filtering
  dynamic top-k
  allowed-code boundary
  lexical boost
  dedup property_code
  query/retrieval cache
  incremental index بر اساس signature ملک
  index persistence در instance/data/rag/lands_index.json

FAISS/Qdrant/Chroma adapterها وجود دارند، اما dependencyهای آن‌ها در
requirements اصلی الزامی نیست؛ استفاده production نیازمند نصب/config جداست.

11.4 Parallel Collaboration
----------------------------

Dependency DAG:
  Wave 0: Property Search || Customer Memory
  Wave 1: Property Analysis
  Wave 2: Recommendation
  Wave 3: Negotiation
  Wave 4: Customer Success

اجزا:
  RuleExecutionPlanner
  StaticDependencyGraphBuilder
  ThreadPoolParallelExecutor
  CompactAgentResultMerger

shared context بین Agentها reuse می‌شود تا Search/RAG/Memory تکراری کاهش یابد.
VINOR_PARALLEL_AGENTS پیش‌فرض ON است. در حالت OFF، manager ترتیبی استفاده می‌شود.

11.5 تخصص Agentها
------------------

Property Search:
  تأیید route/flags و reuse مسیر RAG/tools

Property Analysis:
  تحلیل rule-based قیمت، موقعیت، امکانات، سرمایه‌گذاری و مقایسه

Recommendation:
  score، match reasons، weaknesses، priority و confidence

Customer Memory:
  پروفایل ساختاری از ترجیحات، بودجه، مکان، علایق و relationship

Negotiation:
  risk، strategy، target/min/max/suggested price، tone و deal probability

Customer Success:
  stage، next action، follow-up type/time، priority و conversion probability

Hintها بودجه‌دارند. در parallel mode، Decision hint یا merge hint به hintهای
تک‌تک Agentها اولویت دارد.

  app/express_partner/routes.py مسئولیت‌های زیادی را متمرکز کرده است.

Conditional cognition:
  Decision/BI/World/LongPlan به parallel prepare path وابسته‌اند.

Ephemeral state:
  World Model، Long Plan، Decision و بخشی از BI request-scoped هستند.

Offline autonomy:
  Learning، Improvement و Business AI background هستند؛ autonomous mutation
  انجام نمی‌دهند. Optimization نیز فقط suggestion با applied=False می‌سازد.

BI hint mismatch:
  flag تزریق وجود دارد ولی wiring prompt مستقل وجود ندارد.

Optional vector stores:
  adapter وجود دارد اما dependency/config production باید جدا تأمین شود.

Dual data paths:
  instance/data در کنار data و app/data احتمال اشتباه عملیاتی ایجاد می‌کند.

Secret hygiene:
  production باید SECRET_KEY، VAPID، API keys و credentialها را از secret/env
  امن بگیرد؛ fallbackهای source نباید مبنای production باشند.

Scheduler duplication:
  cron و in-process scheduler نباید هم‌زمان یک job را اجرا کنند.

Test health:
  در snapshot فعلی سه تست Conversation/Workflow شکست دارند.

Documentation drift:
  هر تغییر Registry، route، feature default یا data store باید این سند را
  به‌روزرسانی کند.
