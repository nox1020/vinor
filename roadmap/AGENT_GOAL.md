# هدف ایجنت Vinor (قفل نهایی)

> منبع حقیقت محصول برای AI Chat.  
> کد: `app/ai/goal.py` · Prompt: `app/ai/config.py` · Schema: `tools_schema_for_voice`  
> چارت: [`PROJECT_CHART.html`](PROJECT_CHART.html)

---

## یک جمله

**وینور یک ایجنت بازاریاب دارد که فقط فایل‌های داخل سیستم را می‌فروشد:** به مشتری بهترین گزینه را پیشنهاد می‌دهد و تا معامله پیگیری می‌کند؛ بازاریاب استخدام می‌کند و هر روز کمک‌شان می‌کند بفروشند.

---

## هویت

| چیست | چیست نیست |
|------|-----------|
| **یک** ایجنت = **یک** بازاریاب فروش | شش شخصیت محصول جدا |
| محل کار = **چت** | راهنمای صفحات سایت |
| هدف = **فروش فایل‌های سیستم** (گرمابسرد) | مشاور عمومی املاک ایران |
| ثبت = ابزار + کارت تأیید | فرم/Workflow سایه |

---

## سه سطح سیستم

| سطح | نقش | مسیر / کد |
|------|-----|-----------|
| **چت AI** | فروش زنده — پیشنهاد فایل، بازدید، معامله | `/ai` · `app/ai/*` |
| **پنل ادمین** | کنترل عملیات از چت — فایل، همکار، پورسانت، پیامک، escalation | `/admin` · چت ops + `admin/*` |
| **APK** | شِل موبایل بازاریاب — WebView روی پنل همکار | repo `apk/` → `https://vinor.ir/express/partner/` |

چت می‌فروشد؛ ادمین از چت عملیات کنترل می‌کند؛ APK همان پنل همکار را روی گوشی می‌آورد (منو و منطق از وب).

---

## دو مسیر کاری (فقط این دو)

1. **خریدار** → معیار → بهترین فایل → پیشنهاد → بازدید → پیگیری → معامله  
2. **بازاریاب** → استخدام یا دستیار روزانه → فایل → آگهی → بازدید → پیگیری → معامله

## هستهٔ زنده چت (schema واقعی)

```
چت → tools هسته + کارت تأیید → instance/data
```

| مخاطب | ابزار در schema |
|-------|-----------------|
| مهمان | `search_lands` · `get_cooperation_info` · `get_application_status` · `propose_partner_application` |
| Partner/Special | `search_lands` · `suggest_next_action` · `draft_listing_copy` · visit/complete/deal/release · `propose_log_call` · `propose_followup` |

شماره تماس بازدید کسب‌وکار: **`09121471301`**

### خارج از schema چت (عمدی)

`offer` / `contract` / `settlement` / `lead` / `task` / `visit_result` / …  
Handler در کد می‌ماند؛ مدل چت آن‌ها را نمی‌بیند — تا ایجنت شلوغ نشود.

---

## پنل ادمین (`/admin`)

کنترل عملیات از **چت ops** — نه محل فروش به مشتری، نه Mission Control چندایجنتی.

| حوزه | کار |
|------|-----|
| **چت عملیات** (خانه) | همهٔ اقدام‌های اصلی با ابزار + کارت تأیید |
| فایل / Express | افزودن·ویرایش·تأیید·رد از چت؛ لیست برای مرور |
| همکاران | تأیید/رد درخواست از چت؛ پروفایل برای مرور |
| مالی | پورسانت / برداشت از چت؛ صفحات لیست اختیاری |
| ارتباط | SMS/پوش همگانی از چت (`propose_broadcast_*`) |
| Escalations | پاسخ سوال AI از چت یا صفحهٔ پیام‌ها |
| مشاهده | مانیتور / flagها در Settings (دفن از هویت اصلی) |

قانون: اگر مسیر چت کوتاه‌تر است، همان اولویت دارد. ثبت = ابزار + کارت تأیید → `instance/data`.

کد: `admin/ops_chat_routes.py` · `app/ai/admin_tools.py` · `admin/routes.py` (handlerهای reuse)

## APK (اندروید)

شِل WebView-only برای همکار اکسپرس — ناوبری و UI از سایت؛ نیتیو فقط پل‌ها.

| چیست | چیست نیست |
|------|-----------|
| WebView روی `express/partner` | اپ نیتیو جدا با منطق فروش |
| FCM · deep link · آپدیت APK · speech/notify bridge | Fragment/BottomNav جدا از وب |
| منو از `/api/menu` (وب) | منوی سخت‌کد نیتیو |

ورود پیش‌فرض: `VinorPartnerUrls.ENTRY` → `/express/partner/`  
کد: repo کنار vinor → `apk/` (`MainActivity`, `VinorPartnerUrls`)

## سایه

- Conversation Workflow برای Partner → skip  
- `VINOR_WORKFLOW_COMMIT_PERSIST` → no-op  
- `app/agents/*` موازی + Decision → hint داخلی فروش؛ هویت محصول نیستند  

---

## قانون تصمیم

1. فروش فایل سیستم؟  
2. مسیر چت کوتاه‌تر؟  
3. یک بازاریاب می‌ماند؟  

اگر نه → اولویت ندارد.  
ادمین و APK: فقط وقتی عملیات یا دسترسی موبایل همکار را جلو می‌برند — جایگزین هویت چت نیستند.
