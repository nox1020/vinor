# هدف ایجنت Vinor (قفل نهایی)

> منبع حقیقت محصول برای AI Chat.  
> کد: `app/ai/goal.py` · Prompt: `app/ai/config.py` · Schema: `tools_schema_for_voice`  
> چارت: [`PROJECT_CHART.html`](PROJECT_CHART.html)

---

## یک جمله

**وینور یک ایجنت بازاریاب دارد که فقط فایل‌های داخل سیستم را می‌فروشد:** به مشتری بهترین گزینه را پیشنهاد می‌دهد، **حافظهٔ هر کاربر را تا معامله** نگه می‌دارد و پیگیری می‌کند؛ بازاریاب استخدام می‌کند و هر روز کمک‌شان می‌کند بفروشند.

---

## هویت

| چیست | چیست نیست |
|------|-----------|
| **یک** ایجنت = **یک** بازاریاب فروش | شش شخصیت محصول جدا |
| محل کار = **چت** | راهنمای صفحات سایت |
| هدف = **فروش فایل‌های سیستم** (گرمابسرد) | مشاور عمومی املاک ایران |
| ثبت = ابزار + کارت تأیید | فرم/Workflow سایه |
| حافظه = **ai_memory** هر کاربر + رویداد فروش | پروفایل مشتری جدا از حافظه |

---

## سه سطح سیستم

| سطح | نقش | مسیر / کد |
|------|-----|-----------|
| **چت AI** | فروش زنده — پیشنهاد فایل، بازدید، معامله | `/ai` · `app/ai/*` |
| **پنل ادمین** | کنترل عملیات از چت — فایل، همکار، پورسانت، پیامک، escalation | `/admin` · چت ops + `admin/*` |
| **APK** | شِل موبایل بازاریاب — WebView روی پنل همکار | repo `apk/` → `https://vinor.ir/express/partner/` |

چت می‌فروشد؛ ادمین از چت عملیات کنترل می‌کند؛ APK همان پنل همکار را روی گوشی می‌آورد (منو و منطق از وب).

---

## دو مسیر کاری (فقط این دو)

1. **خریدار (مهمان)** → معیار → بهترین فایل → پیشنهاد → بازدید → پیگیری → معامله  
2. **بازاریاب (همکار)** → استخدام یا دستیار روزانه → فایل → آگهی → بازدید → پیگیری → معامله  

**فروشنده** زیرنوع مسیر ۲ است — همان UI `express/partner` با `voice=special` (مالک فایل خود). مسیر سوم محصول نیست.

## حافظه (سه لایه — همراه فروش)

| لایه | نقش | کد |
|------|-----|-----|
| **حافظهٔ هر کاربر** | منبع حقیقت شخصی — ترجیح، بودجه، فایل دیده‌شده، بازدید، معامله | `instance/data/ai_memory/{user}.json` · `app/memory/*` |
| **چت · اهداف · خلاصه زنده** | تاریخچه گفتگو، اهداف جلسه، خلاصه همکار | `ai_chats` · `ai_goals` · `partner_live` → `live_summary` |
| **دانش کلی سیستم** | موجودی فایل‌ها — مشترک، نه شخصی | `lands.json` · `app/knowledge` · `app/ai/goal` |

### قوانین حافظه

- رویداد فروش (بازدید · معامله · تماس · رد/علاقه) **مستقیم** در ai_memory نوشته می‌شود — نه فقط از متن چت.
- کوتاه‌مدت منقضی می‌شود؛ بودجه/شهر و liked↔rejected تناقض‌ها حل می‌شوند.
- **ناظر** مرحله (جستجو · بازدید · معامله) به **بازیابی** حافظه اولویت می‌دهد.
- مهمان → لاگین: حافظه و اهداف **ادغام** می‌شوند (`app/memory/merge`).
- پاک‌کردن حافظه: ابزار + کارت **`propose_forget_memory`** (مهمان و partner/special).
- پروفایل مشتری در **سایه** از همان ai_memory ساخته می‌شود — حافظهٔ محصول جدا نیست.

چت حافظه را به prompt می‌آورد؛ رویداد فروش مستقیم ذخیره می‌شود.

## پیگیری (دو لایه — نه هویت جدا)

| لایه | نقش | وضعیت |
|------|-----|--------|
| **ناظر** | نظارت داخلی همیشه‌فعال بر مرحله و هدف هر کاربر (خرید · فروش · بازدید · معامله)؛ مرحله به بازیابی حافظه می‌رسد | داخلی · بدون UI · `supervisor/funnel` · `goals` · `executive` · `ai_funnel` |
| **رسدکننده** | followup خودکار تا نتیجه — SMS/FCM/scheduler بدون تأیید ادمین؛ همکار از `sales_coach` | خودکار · `reach` · `sales_coach` · SMS · FCM |

قانون: **ناظر** پیام نمی‌فرستد و UI ندارد — فقط مرحله و هدف را می‌سنجد و به رسدکننده/چت hint می‌دهد. **رسدکننده** پیگیری پس‌زمینه است — خودکار اجرا می‌شود، نیاز به تأیید ادمین یا کارت ندارد؛ خریدار/فروشنده از `app/reach`، همکار تأییدشده از `sales_coach`. **چت** همچنان برای فروش زنده و اقدام‌های حساس (بازدید، معامله، …) = ابزار + کارت تأیید. ارسال رسد از لایه **ارسال** (SMS · FCM) جدا از **ذخیره** (`instance/data` · `ai_memory`).

## هستهٔ زنده چت (schema واقعی)

```
چت → tools هسته + کارت تأیید → instance/data (+ ai_memory)
```

| مخاطب | ابزار در schema |
|-------|-----------------|
| مهمان | `search_lands` · `get_cooperation_info` · `get_application_status` · `propose_partner_application` · `propose_forget_memory` |
| Partner / Special (فروشنده) | `search_lands` · `suggest_next_action` · `draft_listing_copy` · visit/complete/deal/release · `propose_log_call` · `propose_followup` · `propose_forget_memory` |

شماره تماس بازدید کسب‌وکار: **`09121471301`**

### خارج از schema چت (عمدی)

`offer` / `contract` / `settlement` / `lead` / `task` / `visit_result` / …  
Handler در کد می‌ماند؛ مدل چت آن‌ها را نمی‌بیند — تا ایجنت شلوغ نشود.

## پنل ادمین (`/admin`)

کنترل عملیات از **چت ops** — نه محل فروش به مشتری، نه Mission Control چندایجنتی.

| حوزه | کار |
|------|-----|
| **چت عملیات** (خانه) | همهٔ اقدام‌های اصلی با ابزار + کارت تأیید |
| فایل / Express | افزودن·ویرایش·تأیید·رد از چت؛ لیست برای مرور |
| همکاران | تأیید/رد درخواست از چت؛ پروفایل برای مرور |
| مالی | پورسانت / برداشت از چت؛ صفحات لیست اختیاری |
| ارتباط | SMS/پوش همگانی از چت (`propose_broadcast_*`) |
| Escalations | پاسخ سوال AI از چت یا صفحهٔ پیام‌ها |
| مشاهده | مانیتور / flagها در Settings (دفن از هویت اصلی) |

قانون: اگر مسیر چت کوتاه‌تر است، همان اولویت دارد. ثبت = ابزار + کارت تأیید → `instance/data`.

کد: `admin/ops_chat_routes.py` · `app/ai/admin_tools.py` · `admin/routes.py` (handlerهای reuse)

## APK (اندروید)

شِل WebView-only برای همکار اکسپرس — ناوبری و UI از سایت؛ نیتیو فقط پل‌ها.

| چیست | چیست نیست |
|------|-----------|
| WebView روی `express/partner` | اپ نیتیو جدا با منطق فروش |
| FCM · deep link · آپدیت APK · speech/notify bridge | Fragment/BottomNav جدا از وب |
| منو از `/api/menu` (وب) | منوی سخت‌کد نیتیو |

ورود پیش‌فرض: `VinorPartnerUrls.ENTRY` → `/express/partner/`  
کد: repo کنار vinor → `apk/` (`MainActivity`, `VinorPartnerUrls`)

---

## سایه (لایه ④ — نه دسترسی)

- Conversation Workflow برای Partner → skip  
- `VINOR_WORKFLOW_COMMIT_PERSIST` → no-op  
- `app/agents/*` موازی + Decision → hint داخلی فروش؛ هویت محصول نیستند  
- `customer_memory` از **ai_memory** ساخته می‌شود — حافظهٔ محصول جدا نیست  
- جای لایه **دسترسی** (ادمین/APK) نیست — زیر چت، داخلی، بدون UI

---

## قانون تصمیم

1. فروش فایل سیستم؟  
2. مسیر چت کوتاه‌تر؟  
3. یک بازاریاب می‌ماند؟  

اگر نه → اولویت ندارد.  
ادمین و APK: فقط وقتی عملیات یا دسترسی موبایل همکار را جلو می‌برند — جایگزین هویت چت نیستند.
